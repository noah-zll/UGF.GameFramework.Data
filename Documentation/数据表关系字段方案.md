# 数据表关系字段（引用类型）方案

> 本文档定义在 Excel 配表中直接声明表关系字段的能力：类型行写 `@表名`，单元格写目标表主键值，构建时自动注册隐式关系并做引用校验，运行时生成强类型查询方法。

---

## 1. 概述

在现有类型体系（基础类型/枚举/集合/嵌套/自定义类型）之上，增加**引用类型**：

```
类型行写 @表名  →  底层按目标表主键类型存储  →  构建时注册隐式关系 + 引用校验
                  →  代码生成 GetXxx() 强类型查询方法  →  运行时经 DataRelationIndexer 索引查询
```

- **数据侧零新语法**：单元格只写目标表的主键值（`1001`），或按集合规则写（`[1001,1002]`）。
- **与可视化关系编辑器统一**：表内声明的关系自动并入 `relations.json`，与编辑器连线（显式关系）共用同一套运行时索引，可混用。
- **无二进制格式变化**：引用字段按主键的基础类型（int/long/string）序列化，保持 version=1。

---

## 2. 类型声明规则

### 2.1 基本语法

| 类型写法 | 含义 | 单元格示例 | 生成属性类型 |
|----------|------|-----------|-------------|
| `@Drop` | 引用 Drop 表的一条记录 | `1001` | 主键类型（如 `int`） |
| `@Drop[]` | 引用 Drop 表的多条记录（集合） | `[1001,1002]` | `int[]` |
| `List<@Drop>` | 同上，列表语义 | `[1001,1002]` | `List<int>` |
| `HashSet<@Drop>` | 同上，去重语义 | `[1001,1001,1002]` | `HashSet<int>` |
| `Dictionary<@Drop,int>` | 以 Drop 记录为键 | `{1001:5,1002:3}` | `Dictionary<int,int>` |
| `Dictionary<int,@Drop>` | 以 Drop 记录为值 | `{1:1001,2:1002}` | `Dictionary<int,int>` |
| `List<@Drop[]>` | 嵌套（如掉落套组） | `[[1001,1002],[2001]]` | `List<int[]>` |

### 2.2 语法要点

- `@` 后跟**目标表名**（Excel 文件名不含扩展名），如 `@Drop` 指 `Drop.xlsx`。
- 引用类型可出现在集合元素、键值、任意嵌套深度，位置不受限。
- 表名区分大小写；前后空白自动去除（`@ Drop` 视为 `@Drop`）。
- 引用类型的**底层基础类型由目标表主键类型决定**（构建期从目标表表头解析）。
- `@表名` 不是 `string` 类型，不会被误判为枚举或回退类型（优先级见第 3 节）。

---

## 3. 类型判定优先级（扩展后）

```
1. 基础类型        IsSupported
2. 数组            EndsWith("[]")
3. 注册表集合        List / HashSet / Dictionary（泛型括号深度匹配）
4. 引用类型        StartsWith("@")   ← 新增
5. 自定义类型      类/结构体注册表
6. 枚举            enum:前缀 或 非基础非集合非引用类型名
7. 其他            回退为 string（警告）
```

- `@Drop` 判定先于枚举：避免 `@` 前缀类型被当作枚举名。
- 集合内元素类型递归判定：`List<@Drop>` 的元素走第 4 步。

---

## 4. 解析与序列化

### 4.1 值解析（ExcelParser）

- 引用字段的值解析**按目标表主键类型**执行（int/long/string/…），与基础类型解析完全一致。
- 单元格按 JSON 集合规则书写时，元素逐个按主键类型转换。
- 构建期目标表主键类型未解析到（目标表不在批次内）时：回退为 `string` 存储并输出警告。

### 4.2 二进制格式

- 引用字段**无独立格式**：按主键基础类型定长写入 / 集合走 count+元素 / 字典走 count+键值。
- 文件头类型字符串仍写原声明（如 `@Drop`、`List<@Drop>`），读取端按声明解析元素类型。**version 保持 1**。

### 4.3 元数据收集（构建期）

- 解析时收集每条引用声明：`(表名, 字段名, 目标表, 元素类型, 是否集合/字典)`。
- 供关系注册与代码生成使用，不写入二进制。

## 5. 代码生成（DataRowCodeGenerator）

### 5.1 属性

| 声明 | 生成属性 |
|------|----------|
| `@Drop` | `public int DropId { get; private set; }` |
| `List<@Drop>` | `public List<int> DropIds { get; private set; }` |
| `@Drop[]` | `public int[] DropIds { get; private set; }` |
| `Dictionary<@Drop,int>` | `public Dictionary<int,int> DropCounts { get; private set; }` |

> 属性命名：字段名按原样；若字段名与主键类型名不冲突则保持（如字段 `DropId`）。属性类型 = 底层主键类型（含集合/字典）。

### 5.2 强类型查询方法

按引用语义生成强类型方法，内部调用关系索引：

| 声明 | 生成方法 | 返回 |
|------|----------|------|
| `@Drop`（1:1） | `public Drop GetDrop()` | 单条（无匹配返回 null） |
| `List<@Drop>` / `@Drop[]` / `HashSet<@Drop>`（1:N） | `public Drop[] GetDrops()` | 行数组（空集合返回空数组） |
| `Dictionary<@Drop,V>` | `public Drop GetDrop(int key)`（按引用键） | 单条 |
| `Dictionary<K,@Drop>` | `public Drop GetDrop(int key)`（按本表键） | 单条 |
| `List<@Drop[]>`（嵌套） | `public Drop[][] GetDrops()` | 二维数组 |

生成代码示例（`@Drop`）：

```csharp
public int DropId { get; private set; }

/// <summary>关系字段：Drop（1:1，目标表主键）</summary>
public Drop GetDrop()
{
    var row = GameEntry.GetComponent<DataTableComponent>().GetRelatedOne("Item_Drop_DropId", DropId);
    return row as Drop;
}
```

生成代码示例（`List<@Drop>`）：

```csharp
public List<int> DropIds { get; private set; }

/// <summary>关系字段：Drop（1:N，目标表主键）</summary>
public Drop[] GetDrops()
{
    var rows = GameEntry.GetComponent<DataTableComponent>().GetRelated("Item_Drop_DropIds", DropIds);
    return rows as Drop[];
}
```

> 运行时访问通过 `DataTableComponent` 的扩展方法（见第 7 节），无需额外挂载组件。

### 5.3 命名空间

生成文件自动 `using` 目标表的 DataRow 命名空间（与自定义类型收集逻辑一致）。

## 6. 隐式关系注册（构建期）

### 6.1 生成关系定义

构建数据表时，从收集的引用声明自动生成 `TableRelation`，并入 `relations.json`：

| 引用声明 | 生成关系 |
|----------|----------|
| `@Drop` | OneToOne：Item.DropId → Drop.主键 |
| `List<@Drop>` / `@Drop[]` / `HashSet<@Drop>` | OneToMany：Item.DropIds → Drop.主键 |
| `Dictionary<@Drop,V>` | OneToOne（键维度）：Item 的键引用 Drop.主键 |

- 关系名：`{源表}_{目标表}_{字段名}`（如 `Item_Drop_DropId`），保证唯一。
- 输出到与可视化编辑器相同的 `relations.json`（合并：构建时隐式关系 + 编辑器显式关系）。
- 未配置关系输出目录时：仅生成代码内联查询（回退约定关系名），不写文件。

### 6.2 运行时索引

复用 `DataRelationIndexer`：
- 1:1 → `Dictionary<主键, row>`
- 1:N → `Dictionary<主键, row[]>`（引用集合字段按元素建索引）
- 目标表未加载 → 查询返回 null/空；表加载/重载自动失效重建（既有机制）。

---

## 7. 运行时访问

### 7.1 DataTableComponent 扩展方法

- `DataTableExtension`（`UGF.GameFramework.Data` 命名空间）为 `DataTableComponent` 提供关系查询扩展方法：`HasRelation` / `GetAllRelationNames` / `GetRelated` / `GetRelatedOne` / `GetRelatedIds` / `ReloadRelations`。
- 首次查询时懒加载 `StreamingAssets/DataRelations/relations.json` 并懒订阅数据表加载事件；表重载自动失效索引（沿用现有 `DataRelationIndexer`）。
- 生成代码通过 `GameEntry.GetComponent<DataTableComponent>()` 直接访问，无需挂载组件。

### 7.2 查询语义

| 情况 | 结果 |
|------|------|
| 1:1 命中 | 目标行（转型为强类型） |
| 1:1 无匹配 | null |
| 1:N 命中 | 目标行数组 |
| 1:N 无匹配 / 空引用集合 | 空数组 |
| 目标表未加载 | null / 空数组 |
| 关系未注册（配置缺失） | null，并打警告日志 |

## 8. 构建时引用校验

### 8.1 校验规则

| 检查项 | 规则 | 失败处理 |
|--------|------|----------|
| 目标表存在 | `@Drop` 的表在构建批次/已扫描表中 | 错误，构建失败 |
| 主键类型匹配 | 引用字段与目标表主键类型一致 | 错误，构建失败 |
| 值存在（外键完整性） | 每个引用值必须在目标表主键集合中 | 默认报错；可配置降级为警告 |
| 主键类型可解析 | 目标表主键类型在支持范围内 | 错误，构建失败 |

### 8.2 配置

- 构建设置（DataTableBuilderSettings）新增 `ValidateReferences`（默认开启）。
- 校验需目标表参与本次构建（同批次）或提供已解析的 Schema 缓存；目标表不在批次内 → 跳过值校验并警告。
- 校验在全部表解析完成后执行（保证目标表主键集合完整）。

## 9. 边界情况与限制

| 情况 | 行为 / 限制 |
|------|-------------|
| `@表名` 中表名不存在 | 构建失败（校验开启） |
| 目标表主键为 string | 引用字段按 string 存储，集合/字典同理 |
| 引用目标表的表也是引用字段（级联） | 支持（生成代码可链式调用 `GetA().GetB()`） |
| 循环引用（A↔B） | 支持定义，但运行时注意加载顺序（索引按需构建，无死锁） |
| 值超出目标表主键范围 | 校验报错 / 查询返回 null |
| 空单元格 | 1:1 取主键默认值（0/空串）；集合取空集合 |
| 枚举主键 | 目标表主键为枚举时按 int 存储与查询 |
| 与显式关系重名 | 隐式关系名若与显式冲突，后者警告并覆盖 |
| 引用校验性能 | 大数据量建议仅构建期开启 |

## 10. 完整示例

`ItemConfig.xlsx`：

| Id | Name | DropId | DropIds | DropCounts |
|----|------|--------|---------|------------|
| int | string | @Drop | List<@Drop> | Dictionary<@Drop,int> |
| 主键 | 名称 | 关联掉落表 | 掉落列表 | 掉落数量 |
| 1001 | 铁剑 | 3001 | [3001,3002] | {3001:2,3002:1} |
| 1002 | 法杖 | 3003 | [3003] | {3003:1} |

生成（`DRItemConfig`）：

```csharp
public int DropId { get; private set; }
public List<int> DropIds { get; private set; }
public Dictionary<int, int> DropCounts { get; private set; }

public Drop GetDrop()        => GameEntry.GetComponent<DataTableComponent>().GetRelatedOne("Item_Drop_DropId", DropId) as Drop;
public Drop[] GetDrops()     => GameEntry.GetComponent<DataTableComponent>().GetRelated("Item_Drop_DropIds", DropIds) as Drop[];
public Drop GetDrop(int key) => GameEntry.GetComponent<DataTableComponent>().GetRelatedOne("Item_Drop_DropCounts", key) as Drop;
```

构建产物：
- `ItemConfig.bytes`（二进制，字段类型含 `@Drop`）
- `DRItemConfig.cs`（含强类型查询方法）
- `relations.json` 追加三条隐式关系：`Item_Drop_DropId`、`Item_Drop_DropIds`、`Item_Drop_DropCounts`

运行时：

```csharp
var item = dataTableComponent.GetDataTable<DRItemConfig>().GetDataRow(1001);
Drop drop = item.GetDrop();        // 单条关联
Drop[] drops = item.GetDrops();    // 多条关联
```

## 12. 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 声明语法 | `@表名` | 简洁、不与现有类型冲突、可嵌入任意集合/嵌套 |
| 底层存储 | 目标表主键类型 | 复用基础类型序列化，二进制零变化 |
| 运行时访问 | 生成强类型方法 | 编译期类型安全，与 DR 类风格一致 |
| 关系注册 | 构建期并入 relations.json | 与可视化编辑器统一索引，运行时零配置 |
| 引用校验 | 构建期（可开关） | 配错尽早暴露，避免运行时静默空结果 |
| 运行时访问 | `DataTableComponent` 扩展方法 | 无需挂载组件/单例，生成代码直接可用 |
