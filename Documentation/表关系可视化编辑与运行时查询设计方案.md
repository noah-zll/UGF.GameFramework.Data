# 表关系可视化编辑与运行时查询设计方案

> 本文档定义 UGF.GameFramework.Data 的**表关系**功能：
> 在 Unity 编辑器内以节点连线方式可视化管理数据表之间的关联（一对一、一对多、多对多），
> 运行时通过建立的关系直接查找关联数据。
> 标注为「方案」的为规划能力。

---

## 1. 概述

现有数据表体系以"单表 + 主键查询"为核心（`IDataTable<T>.GetDataRow(id)`），表与表之间的关联需要业务代码手工编写：
遍历目标表逐条匹配外键，重复且易错。

本功能引入**表关系**概念：

```
表关系 = 节点（数据表） + 连线（关联定义）
编辑器内可视化连线编辑 → 保存关系配置 → 运行时关系组件构建索引 → 按关系直接查询关联数据
```

目标：
- **可视化**：在 Unity 编辑器中用节点图编辑表关系，所见即所得
- **类型丰富**：支持一对一（1:1）、一对多（1:N）、多对多（N:M，通过中间表）
- **运行时查询**：给定源表记录 ID，直接获取关联表记录（数组或单条）
- **性能**：基于预构建索引，避免遍历整表

---

## 2. 概念模型

### 2.1 节点（Node）= 数据表

- 每张数据表在画布上是一个节点。
- 节点显示：表名、主键字段、全部字段列表。
- 节点上的**端口（Port）**代表可参与关联的字段，默认暴露主键 `Id` 与全部基础类型字段。

### 2.2 连线（Edge）= 关系

一条关系连接**源表（Source）字段**与**目标表（Target）字段**，方向为 源表 → 目标表。

| 关系类型 | 语义 | 示例 |
|----------|------|------|
| 一对一（1:1） | 源表一条记录对应目标表**至多一条** | Player ↔ PlayerProfile（同 Id） |
| 一对多（1:N） | 源表一条记录对应目标表**多条** | ItemConfig → ItemDrop（drop 表按 ItemId 关联） |
| 多对多（N:M） | 源表一条记录对应目标表多条，反之亦然，**通过中间表** | SkillConfig ↔ BuffConfig（经 SkillBuffRef 中间表） |

### 2.3 关联字段约定

- 默认：源表主键 `Id` → 目标表**外键字段**（如 `ItemId`）。
- 支持任意基础类型字段作为关联键（int / long / string 等，两侧类型需一致）。
- 1:1 与 N:1 要求目标表外键字段**唯一**（编辑器可校验并警告）。

## 3. 关系配置数据结构（方案）

### 3.1 编辑器资产（ScriptableObject）

`TableRelationSet`（编辑器内编辑并保存）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `Nodes` | `List<RelationNode>` | 表节点：表名、画布位置、是否展开字段 |
| `Relations` | `List<TableRelation>` | 关系连线 |

`RelationNode`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `TableName` | string | 数据表名（不含 DR 前缀） |
| `Position` | Vector2 | 节点在画布上的位置 |
| `Expanded` | bool | 是否展开显示全部字段 |

`TableRelation`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `Name` | string | 关系名（图内唯一，运行时查询键） |
| `RelationType` | enum | OneToOne / OneToMany / ManyToMany |
| `SourceTable` | string | 源表名 |
| `SourceField` | string | 源表关联字段（默认主键） |
| `TargetTable` | string | 目标表名 |
| `TargetField` | string | 目标表外键字段 |
| `JoinTable` | string | 仅 N:M：中间表名 |
| `JoinSourceField` | string | 仅 N:M：中间表中指向源表的字段 |
| `JoinTargetField` | string | 仅 N:M：中间表中指向目标表的字段 |
| `Description` | string | 关系说明 |

### 3.2 运行时配置（导出数据）

编辑器资产导出为 **JSON** 到 `StreamingAssets/DataRelations/relations.json`（真机可读）：

```json
{
  "relations": [
    {
      "name": "ItemDrops",
      "type": "OneToMany",
      "sourceTable": "ItemConfig",
      "sourceField": "Id",
      "targetTable": "ItemDrop",
      "targetField": "ItemId"
    }
  ]
}
```

- 运行时只读 `Relations` 部分，节点布局信息不导出。
- 导出时机：关系编辑器工具栏「导出」或与数据表构建联动（构建数据表时一并导出）。

## 4. 编辑器可视化设计（方案）

### 4.1 技术选型

使用 **UnityEditor.Experimental.GraphView**（Unity 2021.3 已内置）绘制节点图：

| 需求 | GraphView 能力 |
|------|----------------|
| 节点拖拽、缩放、平移 | 内建 |
| 连线拖拽、吸附端口 | `Edge` + `Port` + 连接回调 |
| 节点内自定义内容（字段列表） | `Node` 自定义内容容器 |
| 关系类型选择 | 连线完成后弹菜单 / Inspector 编辑 |
| 数据持久化 | 序列化为 `TableRelationSet` |

备选方案：IMGUI 自绘（与现有 `DataTableBuilderWindow` 一致，但连线交互需手写），作为 GraphView 不可用时的降级。

### 4.2 窗口布局

```
┌─────────────────────────────────────────────────────────────┐
│ 工具栏：加载数据表 | 添加节点 | 布局整理 | 校验 | 导出 | 保存  │
├───────────────────────────┬─────────────────────────────────┤
│  节点画布（GraphView）      │  属性面板（Inspector）           │
│  · 节点 = 数据表            │  · 选中节点：表信息/字段列表     │
│  · 端口 = 关联字段           │  · 选中连线：关系类型/字段/名称  │
│  · 连线 = 关系              │  · 校验结果与警告               │
└───────────────────────────┴─────────────────────────────────┘
```

### 4.3 交互流程

1. **加载数据表**：从 `DataTableBuilderSettings.ExcelDirectory` 扫描 .xlsx，解析字段信息（复用 `ExcelParser`），生成节点。
2. **建立关系**：从源表字段端口拖拽到目标表字段端口 → 弹出关系类型菜单（1:1 / 1:N / N:M）→ 生成连线。
3. **编辑关系**：选中连线，在属性面板修改关系名、字段、类型；N:M 需额外指定中间表。
4. **校验**：
   - 关系名唯一、不重名
   - 源/目标字段类型一致
   - 1:1 目标外键唯一（读取数据表实际数据校验并警告）
   - 引用了不存在字段 → 红色错误标记
5. **保存/导出**：保存为 `TableRelationSet` 资产；导出 JSON 到 StreamingAssets。

### 4.4 多对多（N:M）中间表交互

- 画布上显示中间表节点。
- 建立 N:M 时自动生成两条隐式连线（源→中间、中间→目标），合并显示为一条带"中间表"标签的关系。
- 运行时查询 `skill.BuffConfigs` 等价于两步查表：源 → 中间（1:N）→ 目标（N:1）。

## 5. 运行时关系服务（方案）

### 5.1 扩展方法与初始化

为 `DataTableComponent` 提供关系查询扩展方法（`DataTableExtension`，`UGF.GameFramework.Data` 命名空间），无需额外挂载组件：

```
初始化流程（首次查询懒触发）：
1. 读取 StreamingAssets/DataRelations/relations.json
2. 解析关系配置 → RelationRuntimeInfo 列表
3. 根据关系引用的表名，从 DataTableComponent 获取已加载的 DataTableBase
4. 首次查询时懒构建索引（或初始化时全量构建，可配置）
```

### 5.2 索引结构

按关系类型构建：

| 关系类型 | 索引 | 查询复杂度 |
|----------|------|-----------|
| 1:1 / N:1 | `Dictionary<key, IDataRow>`（目标表按外键字段取值） | O(1) |
| 1:N | `Dictionary<key, IDataRow[]>`（目标表按外键分组） | O(1) |
| N:M | 两级：源→中间索引 + 中间→目标索引 | O(1) 或 O(k) |

索引键值类型：int / long / string（由关联字段类型决定）。

### 5.3 查询 API

```csharp
public static class DataTableExtension
{
    // 是否存在关系
    bool HasRelation(this DataTableComponent c, string relationName);

    // 1:N：获取目标表关联记录数组
    IDataRow[] GetRelated(this DataTableComponent c, string relationName, int sourceId);

    // 1:1 / N:1：获取目标表单条关联记录（无则 null）
    IDataRow GetRelatedOne(this DataTableComponent c, string relationName, int sourceId);

    // 获取目标表关联记录的主键数组
    int[] GetRelatedIds(this DataTableComponent c, string relationName, int sourceId);
}
```

强类型便捷扩展（配合生成代码）：

```csharp
// 由代码生成器按关系自动生成（可选）
public static class DataRelationExtension
{
    // 一对一：ItemConfig → PlayerProfile
    public static DRPlayerProfile GetProfile(this DRPlayer player)
        => GameEntry.GetComponent<DataTableComponent>().GetRelatedOne("PlayerProfile", player.Id) as DRPlayerProfile;

    // 一对多：ItemConfig → ItemDrop
    public static DRItemDrop[] GetDrops(this DRItemConfig item)
        => GameEntry.GetComponent<DataTableComponent>().GetRelated("ItemDrops", item.Id) as DRItemDrop[];
}
```

### 5.4 生命周期与缓存

- 索引随 `DataTableComponent` 加载完成后再构建（依赖表数据就绪）。
- 表重载（热更/重新加载）时**自动失效并重建**相关索引。
- 内存占用：索引为引用数组，不复制行数据。

### 5.5 逆关系（反向查询）

- 关系定义方向为 源 → 目标；运行时自动支持反向：`GetRelatedIds("ItemDrops", itemId)` 正向，反向查询"该目标行被哪些源行引用"通过目标表主键在索引中反查（可选）。

## 6. 与现有体系集成（方案）

| 环节 | 集成点 |
|------|--------|
| 表字段解析 | 复用 `ExcelParser` 读取表头/字段/主键信息生成节点 |
| 数据表加载 | 复用 `DataTableExtension.LoadDataTable(name)` 加载关系涉及的表面 |
| 运行时取表 | 复用 `DataTableComponent.GetDataTable(Type)`，按 `DR{表名}` 解析类型 |
| 类型定义 | N:M 中间表即普通数据表，无需特殊处理 |
| 构建流程 | `DataTableBuilder` 构建数据表时可选联动导出关系配置 |
| 设置 | `DataTableBuilderSettings` 增加「关系配置目录」「关系导出目录」 |

## 7. 边界情况与限制

| 情况 | 行为 |
|------|------|
| 关联字段类型不一致 | 编辑器校验报错，禁止连线 |
| 关系名重复 | 编辑器校验报错 |
| 引用不存在的表/字段 | 编辑器红色标记；运行时查询返回空 |
| 目标表未加载 | 懒构建时提示"表未加载"，返回空数组 |
| 1:1 目标外键重复 | 编辑器警告；运行时取第一条 |
| 字符串外键 | 支持（索引类型 string），性能略低于 int |
| 多级关系链（A→B→C） | 由业务代码逐级调用，不自动级联查询 |
| 表数据热更新 | 索引自动重建 |
| N:M 中间表有附加字段 | 附加字段不影响查询，可通过中间表记录访问 |
| 大表全量构建索引 | 初始化耗时，建议启动异步或按需懒构建 |

## 9. 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 编辑器技术 | GraphView（UnityEditor.Experimental.GraphView） | 节点连线交互成熟，2021.3 内置 |
| 关系配置存储 | 编辑器 ScriptableObject + 导出 JSON | 编辑器可引用编辑；运行时真机可读 |
| 运行时访问 | `DataTableComponent` 扩展方法 | 无需挂载组件/单例，生成代码直接可用 |
| 索引策略 | 懒构建 + 表重载自动失效 | 避免启动开销，保证热更正确性 |
| 查询方向 | 正向（源→目标）为主，反向可选 | 满足主要业务场景，控制复杂度 |
| N:M 实现 | 中间表两步查询 | 复用 1:N 能力，无需特殊存储结构 |
